# 搞磁盘下一阶段实施与设备验收计划（未执行）

日期：2026-10-18。本文是下一阶段材料，不授予开发真实写盘工具、安装驱动/扩展、挂载或修改真实介质的权限。V1.00 的本次安装范围仍为普通镜像只读分析 App。研究结论及语义门槛见 [SafetyDesign.md](SafetyDesign.md)。

## 1. 推荐顺序和进入门槛

建议继续的唯一默认路线是**只读优先**：完善受限解析器、样本和报告 → 在普通可丢弃镜像上验证引擎适配 → 单独审查是否需要系统文件系统接入。成熟开源引擎、商业 SDK、FSKit 和兼容层的选择必须依据当日官方证据与许可证结论，本文不预定它们已经可用或可商用。FSKit 只作为未来可能的接入层；NTFS 语义、日志与恢复能力必须由明确引擎承担，不能靠框架名称推定。

阶段划分：

| 阶段 | 允许的范围 | 进入下一阶段的证据 |
|---|---|---|
| A：V1.00 当前交付 | 普通文件只读解析、合成坏样本、构建/签名/安装只读 App | 实现能力及限制有源码/测试对应；无真实卷/驱动接口；发行内容审计 |
| B：只读引擎验证 | 在隔离普通镜像上编译/链接候选引擎，核对合法来源和许可 | 独立安全复核、资源预算、功能矩阵、官方证据、无块设备句柄 |
| C：只读系统接入研究 | 设计接入边界、审批和签名条件；获具体授权后才在专用测试环境验证 | 平台/架构证据、最小权限审查、卸载/恢复演练；没有写能力 |
| D：可丢弃镜像受控写入 | 只有用户另行明确授权该阶段，才可写指定镜像副本；不自动扩展到设备 | 全语义矩阵、差分证据、故障注入、恢复证据、独立安全/许可审查 |
| E：专用可清空外置盘实验 | 用户逐项确认具体空白介质和破坏动作后，执行限定批次 | Windows 双向验证、失败封存、硬件证据、可重复结果和明确停止条件 |
| F：产品/发行评审 | 独立决策；不是研究成功后的自动动作 | 支持范围、签名/公证/权限、许可、恢复、分发与更新均达标 |

阶段之间不得以“继续”或之前的安装请求推定真实写盘授权。引擎适配成功、镜像测试通过、文件能枚举均不等于设备写入安全。

## 2. 需要的专用资源

- 至少两块可完全清空的外置测试盘及稳定连接线/电源；容量、接口和设备标识由后续实物盘点填写。建议分别用于基线与故障注入，不使用唯一副本或个人资料盘。
- 独立 Windows 参考系统，能在不接触个人卷的条件下创建、检查和比对 NTFS 测试卷；具体 Windows 版本、构建号、CPU、工具及版本需现场记录，不预先声称已覆盖。
- 可重新安装/恢复的 macOS 测试环境；如路线要验证 Intel，必须有真实 Intel 设备，Apple Silicon 编译或模拟结果不能替代。
- 独立保存的源镜像、只读基线副本、摘要清单、测试内容生成脚本、故障前后镜像、Windows 侧报告和备份恢复介质；它们与被测试盘物理分离。
- 专门用于断电/断连注入的可清空硬件、可重复操作方式和记录工具；不能在日常宿主正在处理真实资料时模拟宿主崩溃。

设备仍未提供，全部硬件项为**未验证**。测试中产生的真实设备编号、卷标或私密路径只存本地受限记录；发行与公开仓库只保留生成器和脱敏结果。

## 4. 具体介质及破坏操作的授权门槛

后续请求授权前，必须先完成可复核方案和只读盘点。授权应由用户对**实物与本批操作**明确确认，不能仅确认路径或卷名：

1. 显示设备型号、容量、序列/稳定标识的本地确认方式、连接位置、分区图、当前卷标和需要清空的范围；敏感编号不进入公开日志。
2. 用户确认该盘可全部清空、没有唯一资料；给出已核验备份清单、摘要与恢复演练结果。读不到或路径缺失不能当空盘。
3. 列明本批具体动作：重分区、格式化、写入哪些范围、删除哪些测试数据、何种断电/热拔插/故障注入；分别列出不可逆影响与预期恢复方式。
4. 明确禁止触及的宿主内置盘、其它外置盘及个人卷，给出独立操作者复核和设备身份二次核验步骤。授权后设备身份变化必须停止并重新确认。
5. 用户确认之后才取得相应权限；系统密码、Touch ID、系统批准均由用户在系统界面完成，不代填、不存储、不改保护数据库。
6. 每批的时间、设备、软件版本、范围和允许故障必须写入本地记录。首次授权不自动覆盖更换设备、新增破坏操作、扩大范围或产品发行。

App 安装、编译、签名或普通镜像选择授权不能替代上述授权。未满足时仍可继续文档、静态检查和普通文件只读测试。

## 5. 内容与语义验收流程

在专用 Windows 参考系统生成确定性测试集与清单：相对名称/原始编码、内容摘要、长度、所有流及摘要、属性、时间戳、SID/ACL、链接关系、重解析数据、配额、压缩/稀疏布局和分配证据。原始清单仅在受限环境保存；公开材料使用纯合成名称。

按以下顺序运行，任何阶段失败不得自动跳到下一阶段：

1. **Windows 创建**：在已授权空白卷生成小文件、空文件、多 GB 大文件、随机内容、跨边界文件、ADS、多用户权限/继承拒绝、Unicode 与大小写冲突、超长与保留名、硬/符号链接、reparse、压缩和稀疏。记录工具/系统/参数。
2. **Windows 基线**：独立读取和摘要验证；将合法来源的基线镜像与清单封存。NTFS 检查工具仅检查本批空白测试卷，其运行本身的修改行为须明确授权和记录。
3. **macOS 只读**：仅允许已支持语义；对每字段和内容流与基线逐项比较；对不支持特性必须显示不支持/拒绝，不能静默降级。宿主导出验证与卷内语义验证分开。
4. **受控写入**：仅在阶段 D/E 另获授权后，在指定副本或测试介质按单操作批次写入；每批前后保存摘要、操作日志与空间/元数据状态，不同时做多种无法归因的变化。
5. **Windows 回验**：验证内容摘要、大小、全部 ADS、属性/ACL/SID、Unicode 原始名称和冲突、时间戳精度、链接身份/计数、压缩/稀疏分配、大文件与配额。只对测试卷做获准检查；检查通过不能覆盖内容或权限差异。
6. **关机会话**：核验正常关闭、睡眠/唤醒、重连与新会话状态。失败记录不得清空为成功；输出通过/失败/不支持/未验证四类结果及证据。

dirty、休眠、BitLocker、EFS、未知属性/日志版本、损坏结构等样本主要验证**识别与拒绝**，不能将其纳入默认“尝试兼容写入”集合。

## 6. 故障矩阵与失败判据

以下均是未来计划，未在 V1.00 对真实硬件执行。断电、系统崩溃及驱动崩溃只允许发生在专用可恢复环境，具体故障需逐批授权。

| 故障 | 注入阶段 | 应有反应 | 验收与停止条件 |
|---|---|---|---|
| 写中断电 | 内容、元数据、日志/提交屏障前后分别注入 | 停止会话；重启/重连只读探测，进入恢复阻断 | 任意未解释结构变化/丢流/越界写即停止；恢复边界无证据判失败 |
| 热拔插/连接抖动 | 读、写、刷盘、关闭各阶段 | 使句柄/缓存失效，拒绝继续旧队列 | 重插设备误识别、继续旧写或 UI 伪报完成即失败 |
| 满盘/配额耗尽 | 数据分配、扩展元数据、日志预留 | 停止新写入，不删除用户数据、不放宽语义 | 出现不完整事务、泄露分配、错误 success 即失败 |
| 宿主崩溃/强制重启 | 会话打开、批次中、关闭时 | 启动后不自动重放；保留已确认边界 | 无法辨认已提交/未提交、账本丢失自动放行即失败 |
| 引擎/驱动/服务崩溃 | I/O 在途、屏障及恢复阶段 | UI 与权限组件分离，冻结相关卷 | 高权限组件失控、无界重试、其它卷受影响即停止路线 |
| 睡眠/唤醒 | 空闲、I/O 在途、刷盘 | quiesce；不能确认则阻断，醒后重新探测 | 睡醒自动恢复可写或状态误判即失败 |
| 并发访问/外部改变 | 第二实例、其它进程/系统访问 | 单卷锁和身份变化检查生效 | 两个写入者同时成功、缓存陈旧、权限冲突即失败 |
| 只读宿主 I/O 错误 | 短读、权限撤销、源文件替换 | 明确宿主故障，不修复源文件 | 误报 NTFS 损坏并调用修复/格式化即失败 |
| 恢复记录异常 | 缺失、截断、摘要错、过新版本 | fail closed，保留最后有效状态和恢复入口 | 新建空记录解除阻断、重放任务即失败 |
| 名称/流/权限异常 | 冲突、循环、ADS 不支持、SID 未知 | 识别、拒绝相关操作、显示范围 | 静默改名、丢流、放宽权限后成功即失败 |

故障后先冻结测试，保留设备原状；在获得只读安全手段后封存“故障后”镜像、只读基线、摘要清单、版本/配置和事件时间线。对比内容、结构、分配、权限、流和状态记录，区分引擎、应用及宿主 I/O 原因。原始损坏副本不做修复实验；仅从封存副本克隆另一份，另获授权才运行修复。不能证明恢复、差异无法解释或需要猜测成功时判失败。

全局停止条件：触及未授权设备、设备身份不符、备份不可恢复、许可证不明、平台权限无法合法取得、源文件/真实介质被意外写入、越界访问、关键语义丢失、不支持状态被写入、恢复不确定、证据不完整或结果不可重复。立即停止后续破坏测试，保留证据并报告，不用扩大权限或再次写入掩盖问题。

## 8. 下一阶段评审结果模板

每次报告应明确：实际改动与版本、只读能力/拒绝范围、执行的静态和隔离检查、未运行的冒烟及硬件项、源镜像前后摘要、真实资料保留、许可和签名状态、安装/发行事实、异常/停止原因。尚无证据的“兼容”“完整”“安全”“可恢复”“通过”不能用作结论。
